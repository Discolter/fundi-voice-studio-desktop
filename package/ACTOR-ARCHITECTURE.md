# Fundi Voice Studio 1.4 / Cloud 0.2 / Actor 0.1

Реализован первый рабочий цикл: подключение Studio, публикация,
приглашение, аккаунт, персональные проекты и долги актёра.
Развёрнутый сервер обновляется пользователем из архива Cloud.

## Границы

Studio — Windows-программа владельца, источник назначений и статусов.
Actor — отдельная Windows-программа; только чтение своих проектов и долгов.
Cloud — один экземпляр ASP.NET Core 10 с PostgreSQL для одной студии.

Telegram — контакт в локальной карточке. Авторизация использует внутренний actorId,
логин и пароль. Переименование Telegram не меняет назначения и доступ.
Новые актёры по умолчанию имеют actorAccess=false.

## Публикация

Сохранение workspace.json вызывает независимую проекцию ActorProjection в C#.
Она формирует только разрешённый контракт: ID проекта/серии/роли, название,
персонаж, статус и срок. Архивные проекты и запрещённые актёры исключены.
На сервер не передаются заметки, папки, ресурсы, Telegram, аватары или медиа.

Очередь cloud.pending.json сохраняется между запусками и объединяет изменения.
Публикация имеет requestId и baseRevision. Сервер применяет весь снимок атомарно.
Повтор запроса не создаёт второе обновление; конфликт требует решения владельца.
Первая привязка к непустому серверу также требует подтверждения публикации.

## Учётные записи

Первый ключ STUDIO_SETUP_KEY генерируется Studio и добавляется владельцем в Render.
Подключение одноразовое. На сервере сохраняются только хэши кода и токена устройства.
Повтор того же запроса с тем же устройством безопасен при потере ответа.
Новая привязка владельца отзывает старый токен Studio.

Приглашение действует 24 часа, хранится как хэш и используется один раз.
Актёр выбирает собственный логин и пароль. Новый активированный код может
восстановить его аккаунт и завершает старые сеансы.
Пароли: PBKDF2-SHA256, отдельная соль, 600000 итераций.
Access-токен живёт 15 минут, refresh — 30 дней. Refresh ротируется;
повтор использованного токена отзывает семейство сеанса.

На каждом запросе личность извлекается из серверного сеанса.
Actor не может передать другой actorId в запрос /roles.
Отключение актёра отзывает его сеансы и неиспользованные приглашения.
Это происходит после успешной публикации отключения из Studio.

## Windows-клиенты

Ключи Studio и сеанс Actor шифруются Windows DPAPI CurrentUser.
Они не выдаются в JavaScript и не входят в экспорт workspace.json.
Локальные мосты слушают только 127.0.0.1 и требуют случайный ключ и правильный Host/Origin.
Облако вызывается из C# через HTTPS с обычной проверкой сертификата Windows.

Actor сохраняет последний собственный список внутри защищённого session.bin.
Без сети показывает время последнего обновления. Выход и подтверждённый отзыв
доступа очищают локальный сеанс и кеш. Уже просмотренное ранее нельзя отозвать
с чужого компьютера задним числом.

Actor опрашивает сервер раз в минуту, включая работу в трее.
Windows-уведомления появляются о новых ролях и переходе на перезапись.
После полного завершения приложения уведомлений нет.

## Что остаётся проверить на целевых устройствах

Нативный запуск Windows 10/11, DPAPI профиля, трей, уведомления и доступность
серверного адреса у конкретных российских провайдеров.
В среде разработки проверены компиляция C# 5/.NET Framework 4.8,
интерфейсы в Chromium и API с Npgsql поверх TLS и изолированного PostgreSQL/WASM.
Docker локально не запускался.

Автоматический установщик обновлений приложения и загрузка медиа не включены.
